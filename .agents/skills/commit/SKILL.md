# Commit

프로젝트의 변경사항을 안전하게 검토하고, 기존 커밋 컨벤션에 맞춰 저장한다.

## 절차

1. `git status --short`와 `git diff`로 작업 트리의 변경사항을 확인한다. 스테이징된 변경이 있으면 `git diff --staged`도 확인한다.
2. 변경사항을 기능, 버그 수정, 리팩터링, 설정·유지보수처럼 독립적으로 되돌리거나 이해할 수 있는 논리적 단위로 분류한다. 관련 없는 변경을 하나의 커밋에 섞지 않는다.
3. 저장소의 최근 커밋 메시지를 확인해 기존 관례가 있으면 따른다. 한국어 Conventional Commit 형식으로 각 커밋 메시지를 작성한다.

   ```text
   feat: 컴포넌트 미리보기 새로고침 추가
   fix: 빈 프롬프트 생성 요청 차단
   refactor: 생성 API 호출 로직 분리
   chore: 개발 의존성 업데이트
   ```

4. 커밋할 파일, 논리적 단위, 제안 메시지를 사용자에게 간결하게 보여주고 명시적인 승인을 요청한다. 승인 전에는 `git add`나 `git commit`을 실행하지 않는다.
5. 사용자가 승인하면 승인된 범위의 파일만 스테이징하고 커밋한다. 완료 후 커밋 해시와 메시지를 보고한다.

## 판단 기준

- 사용자 또는 다른 작업자가 만든 관련 없는 변경은 건드리지 않는다.
- 변경사항이 없으면 커밋 대신 작업 트리가 깨끗하다고 알린다.
- 하나의 변경이 여러 논리적 단위에 걸치면, 파일·hunk 단위로 안전하게 분리할 수 있을 때만 나눈다. 그렇지 않으면 이유를 설명하고 하나의 응집된 커밋으로 제안한다.
- 자동 생성 파일, 비밀 정보, `.env` 파일은 내용과 추적 상태를 확인한 뒤 명시적으로 필요할 때만 포함한다.
